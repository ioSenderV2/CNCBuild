Fetching notes

  • Both waveshare.com URLs return HTTP 403 to a plain fetch — curl with no user agent, and most scripted downloaders. They serve normally with a browser User-Agent:
    curl -L -A "Mozilla/5.0" -o FILE URL
  • cdn.amphenol-cs.com is behind a Cloudflare JavaScript challenge — curl and scripted fetches get an HTML challenge page with HTTP 403, not a PDF. Watch for a ~6 KB "PDF": that is the challenge page, not the drawing. Download it in a browser.
  • mouser.com blocks automated fetches too ("Access Denied ... automation tools"), and returns that page with HTTP 200 and Content-Type: text/html — so a naive download script saves a ~14 KB "PDF" and reports success. Always check file type or page count after fetching.
  • The vendor wiki page for the module is waveshare.com/wiki/ESP32-S3-RS485-CAN (same 403 behaviour); the schematic is linked from its Resources section.
  • ams-OSRAM's own product page has moved at least once. The mirror above is stable and is the revision these documents were read against — prefer it over a search result, since figure and table numbers cited in this repo are revision-specific.

Adding an asset

  1. Save the file into this folder.
  2. Add a row above: part, vendor, what it is, exact filename, the URL it came from, today's date.
  3. Commit only this index.html. The .gitignore here already excludes everything else, so the file itself will not be staged by accident.
